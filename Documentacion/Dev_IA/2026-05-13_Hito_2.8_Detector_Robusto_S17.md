## 2. Cambios implementados

### 2.1 detector.py — Arquitectura multi-capa

**Antes:** una sola capa de template matching con threshold 0.85 global.

**Después:**
- **Capa 1 (rápida):** template matching con threshold DINÁMICO por estado
  - S3/S6/S7/S10 (captura crítica): 0.85
  - S17/S18 (información): 0.75
  - S13/S14/S15 (transición): 0.70
- **Capa 2 (verificación secundaria):** funciones de confirmación por estado
  - Verificar elementos UI únicos (texto, color, layout)
- **Capa 3 (HSV fallback):** clasificación por paleta de color
  - S10: barra EXP verde + fondo modal oscuro
  - S11: header rojo desmontaje
  - S13: fondo de mapa/nodo

### 2.2 Slot detection multi-método para S17

**Antes:** solo OCR del título `"Set Name (N)"` con Tesseract.

**Después (fallback chain):**
1. **Método A — OCR del título** (confianza > 0.8 → OK)
2. **Método B — Aro brillante HSV** (slot seleccionado tiene glow verde/amarillo)
3. **Método C — Template matching por slot** (6 templates pequeños)

### 2.3 Captura de disco desde S17

- S17 movido de `NON_CAPTURE_STATES` a `CAPTURE_DISC_STATES`
- `monitor.py`: agregado S17 a `_DISC_DETAIL_STATES`
- `parser_disc.py`: agregada sección `modal_detalle_s17` en `_STATE_TO_ROI_SECTION`
- `rois.toml`: agregada sección `[modal_detalle_s17]` con ROIs calibradas

### 2.4 State machine

Nueva clase `StateMachine` que valida transiciones entre estados:

```
None → {S1, S4, S12, ...}
S1   → {S2, S12, S13, ...}
S2   → {S3, S12}
S3   → {S12, S11}
...
S8   → {S17, S18, S12}
S17  → {S8, S18, S12}
S18  → {S8, S12}
```

Si un estado detectado no es una transición válida → se reporta como S12 (FP)

## 5. QA — Pasos de prueba en el juego

### 5.1 S17 — Detección de slot + disco desde Personalización de pistas

```
1. Abrir ZZZ → Menú principal
2. Ir a "Personajes" → seleccionar cualquier PJ
3. Click en "Personalización de pistas de disco" (S17 debe detectarse)
4. Verificar en log/app: estado=S17, slot=N detectado
5. Clickear cada slot 1→2→3→4→5→6
   → slot debe actualizarse correctamente cada vez
6. Verificar que el disco equipado se parsea: set, mainstat, substats, nivel
```

**Criterio de aceptación:** ≥ 10/12 slots detectados correctamente.

### 5.2 S18 — Perfil agente atributos base

```
1. Desde Personalización de pistas (S17), click en "Atributos base"
2. S18 debe detectarse (cualquiera de los 3 templates)
3. Verificar que NO hay intento de captura de disco (es informativo)
4. Volver a Personalización de pistas → S17 debe detectarse nuevamente
```

### 5.3 Anti-FP — Transiciones inválidas

```
1. Abrir y cerrar modal de recompensa diaria
   → NO debe detectarse como S3
2. Ir a Pantalla de desmontaje (S11)
   → NO debe capturar discos aunque aparezcan tiles con NEW!
3. Clickear en modal "Información de conjunto" (S16)
   → NO debe detectarse como S3/S6/S7
```

### 5.4 S13/S14/S15 — Pantallas de transición

```
1. Ir a selección de set de farmeo (nodo boss): S13
2. Ir a selección de equipo pre-combate: S14
3. Ir a menú de personajes: S15
   → Todas deben detectarse y NO intentar captura
```

### 5.5 S3/S6/S7 — Captura normal (regresión)

```
1. Farmear un disco → S2 (resultado desafío) → click drop → S3 (modal detalle)
   → Disco debe parsearse correctamente
2. Tienda música → afinar → S5 → click detalle → S6/S7
   → Disco debe parsearse correctamente
```

### 2.5 Dark frame filter (anti-FP)

Nuevo filtro en `classify()` capa 0: si > 50% del frame tiene brillo < 35, se clasifica
como S12 inmediatamente (pantalla de carga / diálogo oscuro). Previene FPs en
transiciones que no deberían ser reconocidas como ningún estado.

**Caso concreto:** screenshot `Dispara_disco_descarte.png` (75.7% píxeles < 30 brillo)
ahora se clasifica como `S12 dark_frame_filter` en lugar de intentar template matching.

Ver también `app/tests/unit/test_detector_fp_regression.py` (5 FPs parametrizados).
