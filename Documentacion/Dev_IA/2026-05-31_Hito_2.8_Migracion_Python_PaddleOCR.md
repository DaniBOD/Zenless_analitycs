## 2. Cambios implementados

### 2.1 Migración de Python Windows Store → Python 3.11.9 normal

**Procedimiento (manual, guiado paso a paso):**

1. Pre-flight: backup de `pip freeze` + version snapshot a `tools/pip_snapshot_winstore_*.txt` y `tools/python_version_pre.txt`.
2. Descarga e instalación de `python-3.11.9-amd64.exe` desde python.org (path por defecto: `C:\Users\danie\AppData\Local\Programs\Python\Python311\`).
3. Activación de "Disable path length limit" (sube `MAX_PATH` de 260 a 32K).
4. Creación de venv: `C:\Users\danie\AppData\Local\Programs\Python\Python311\python.exe -m venv .venv`
5. Activación: `.\.venv\Scripts\Activate.ps1` (requirió `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` una vez).

**Gotcha del Python Install Manager:** el usuario inicialmente descargó `python-manager-26.2` desde python.org pensando que era Python 3.11.9. PyManager es una herramienta wrapper distinta del intérprete. La sección "Files" de la página de release del 3.11.9 tiene el instalador clásico — hay que scrollear hasta abajo. Documentado para próximas iteraciones.

**Gotcha de App Execution Aliases:** Windows Store Python sigue interceptando el comando `python` aunque el de python.org esté instalado y en PATH. No es bloqueante mientras se trabaje dentro del venv (donde el `python` apunta al venv), pero el PATH global queda con el de Store primero. Optativo: desactivar en Settings → Apps → Advanced app settings → App execution aliases.

### 2.2 Fix del `pyproject.toml` — build-backend inexistente

**Archivo:** [`pyproject.toml`](../../pyproject.toml)

Línea 27 declaraba un backend que **no existe en setuptools**:

```toml
# Antes (rompe en pip 26+)
build-backend = "setuptools.backends.legacy:build"

# Después
build-backend = "setuptools.build_meta"
```

Pip 24 lo dejaba pasar silenciosamente (fallback). Pip 26 valida estricto y aborta con:

```
pip._vendor.pyproject_hooks._impl.BackendUnavailable:
Cannot import 'setuptools.backends.legacy'
```

Era un typo latente desde la creación del proyecto. Se descubrió al intentar el primer `pip install -e ".[dev]"` post-migración.

### 2.4 Fix del test rol-aware — comparación case-sensitive

**Archivo:** [`app/tests/unit/test_parser_agent_stats.py`](../../app/tests/unit/test_parser_agent_stats.py) (líneas 85-91)

El test `test_extracts_all_11_stats[atributos_base_ejemplo_7]` falla con:

```
AssertionError: Stats faltantes o cero en atributos_base_ejemplo_7:
solo 10/11 (rol=Disruptivos, min_expected=11).
...pen_rate=None er=2.0
```

**Diagnóstico:** PaddleOCR extrajo correctamente 10 stats (todos los esperados para un Disruptivo); el 11vo que el test exigía es `tasa_perforacion`, pero **los Disruptivos no tienen ese stat en pantalla** — su lugar lo ocupa `fuerza_bruta`. La lógica rol-aware ya estaba implementada en el test (línea 87 original):

```python
# Antes
min_expected = 11 if result.rol != "disruptivos" else 10
```

Pero la comparación era **case-sensitive**. El parser devuelve `"Disruptivos"` (mayúscula inicial, como en UI del juego), entonces `"Disruptivos" != "disruptivos"` evaluaba True → `min_expected = 11` → fail.

**Fix:** alinear con la lógica del controller (`app/ui/controller.py` sección 2.6 del dev log 2026-05-27) — lowercase + substring match:

```python
# Después
rol_norm = (result.rol or "").lower()
is_disruptivo = "disruptiv" in rol_norm
min_expected = 10 if is_disruptivo else 11
```

Maneja:
- Case-insensitive (`"Disruptivos"`, `"DISRUPTIVOS"`, `"disruptivos"` → todos válidos)
- `None`-safe
- Substring match (tolera `"Disruptivo"` singular, o casos OCR con sufijos)

## 7. Lecciones aprendidas

- **Pip 26 es estricto con `build-backend`.** Lo que pip 24/25 dejaba pasar ahora aborta. Cualquier proyecto Python que arrastre `pyproject.toml` viejos debería auditar el `[build-system]`.
- **Python Install Manager (PyManager) ≠ intérprete de Python.** Confusión común; la página de release de python.org promociona PyManager arriba y el instalador clásico abajo en la sección "Files".
- **Comparaciones de OCR siempre normalize.** El parser devuelve `"Disruptivos"` con la capitalización exacta del juego. Tests + lógica de negocio deben hacer `lower()` + substring match, no equality.
- **Pins de PyPI fallan silenciosamente en docs.** Versiones que nunca se publicaron (como `paddleocr==2.8.2`) se descubren solo al intentar instalar. Verificar en `pip index versions <pkg>` antes de documentar pins.
- **Migrar a venv siempre que sea posible.** El venv aisla del PATH global y de los App Execution Aliases del Store. Una vez activado, las preguntas de "qué python responde" desaparecen.
