## 0. Diagnóstico — por qué los tests no atrapaban el bug

Los 148 tests previos (incluidos los 17 sobre `parse_agent_stats[1-7]`)
verificaban **solo el parser** llamando `parse_agent_stats(frame, ocr)` con
los 7 fixtures directamente. **Ningún test invocaba el pipeline real** del
detector (`ScreenDetector.classify()`) ni el dispatch del monitor
(`Monitor._dispatch_state()`). Cero cobertura sobre la cadena:

```
frame → ScreenDetector.classify() → [TemporalBuffer] → _dispatch_state →
        _maybe_process_agent_stats → parse_agent_stats → on_agent_stats CB
```

Resultado: aunque el parser estaba perfecto, en runtime la cadena se
rompía antes de llegar a él. Los tests "pasaban" sin tocar el camino que
fallaba en el `.exe`.

### 0.1 Causas concatenadas (todas ya documentadas en §12.3 del seguimiento)

| # | Eslabón | Por qué falla en `.exe` 2560×1440 |
|---|---------|-----------------------------------|
| 1 | `_template_match()` | Las 3 templates S18 fueron capturadas a una resolución/UI ligeramente distinta. `cv2.matchTemplate` no rescata por escalado. |
| 2 | `_verify_s18()` | Es reactiva (solo corre cuando template ya dio S18). Si template falla, los 4 indicadores nunca se evalúan. |
| 3 | `_classify_by_hsv()` para S18 | `HoughLinesP` con `threshold=40, minLineLength=0.3×width` no detecta la grilla a 2560×1440. |
| 4 | `_VALID_TRANSITIONS["S13"]` | No incluía S18. Si el detector llegaba a un S13 parcial antes, transición S13→S18 invalidada. |
| 5 | `_is_dark_frame()` | A veces filtra como S12 inmediato pantallas con fondo oscuro del personaje. |

Encadenado: `classify()` jamás devolvía S18 → `_dispatch_state` no
matcheaba `AGENT_STATS_STATES` → `_process_agent_stats` no corría →
`on_agent_stats(stats, state)` nunca se invocaba → `[stats]` jamás en log.

## 1. Solución implementada — Deep S18 Multi-Trigger

Nuevo detector independiente `_deep_detect_s18(frame, ocr) → ScreenState | None`
en [`app/core/detector.py`](../../app/core/detector.py). Diseño:

- **Resolución-agnóstico** — todas las ROIs son fracciones del frame.
- **Independiente de templates** — no requiere match previo.
- **Score-weighted con gating OCR** — promoción a alta confianza
  requiere al menos un indicador OCR que devuelva texto distintivo de S18.
- **Corre como fallback** en `monitor._run()` cuando `classify()` devuelve S12.

### 1.1 Indicadores y pesos

| # | Indicador | Helper | Peso | Característica |
|---|-----------|--------|------|----------------|
| 1 | Subrayado amarillo del tab "Atributos base" | `_s18_visual_tab_amarillo` | 1 | HSV inRange. Robusto cuando dispara, ruidoso (1/7 fixtures). |
| 2 | Grilla de stats ≥4 líneas paralelas | `_s18_visual_grilla_stats` | 1 | Canny + HoughLinesP. Comparte con S16 (Detalle set disco). |
| 3 | Valores numéricos brillantes col. derecha | `_s18_visual_valores_brillantes` | 1 | Bright pixel ratio. Sensible al contraste. |
| 4 | "AGENT INFO" texto sutil (CLAHE+threshold) | `_s18_visual_agent_info_clahe` | 2 | Firma visual fuerte (7/7 fixtures). Calibrado con `std>15` + `0.03<text_area<0.95` para descartar frames uniformes. |
| 5 | OCR detecta "AGENT INFO" / "Atributos base" en banner | `_s18_ocr_agent_info` | **2** | Tesseract sobre ROI normalizada superior-izq. **Exclusivo de S18.** |
| 6 | OCR detecta ≥3 grupos de keywords stats | `_s18_ocr_stat_keywords` | **2** | Tesseract sobre panel central. Acepta variantes ES (PV, Ataque, Defensa, Impacto, CRIT, Anomalia, Maestria, Perforacion, Recuperacion, Energia). |

### 1.2 Reglas de decisión

```text
visual_score = sum(visuales hits)           # 0-5
ocr_score    = sum(OCR hits) * 2            # 0-4
total        = visual_score + ocr_score

if ocr_score >= 2 and total >= 3:
    → S18 confianza 0.75, method="deep_detect"        # alta conf, requiere OCR
elif total >= 2:
    → S18 confianza 0.55, method="deep_detect_tentativo"
else:
    → None
```

**Razón del gating OCR para alta confianza:** los indicadores visuales 2
(grilla) y 4 (CLAHE) también disparan en S16 (modal "Información de
conjunto"). Sin la firma textual ("AGENT INFO" / keywords stats), no se
puede distinguir S18 de S16 por píxeles. La señal OCR es el discriminador
necesario. Esto se verificó empíricamente sobre los 5 fixtures FP en
`Documentacion/Screenshots_Triggers/Triggers_Generales/Falsos_positivos/`.

### 1.3 Calibración empírica (QA sobre 7 fixtures + 5 FPs)

| Source | CLAHE std | text_area | Resultado |
|--------|-----------|-----------|-----------|
| S18 fixtures (`atributos_base_ejemplo_*`) | 38-103 | 0.50-0.74 | ✅ CLAHE fire (7/7) |
| FP modales S16 (`Detalle_set_disco_*`) | 7-8 | 1.00 | ✅ Filtrado por `std<15` |
| Frame negro de transición | 0 | 1.00 | ✅ Filtrado por `std<15` |

## 2. Wiring en el monitor

[`app/core/monitor.py:163-185`](../../app/core/monitor.py)

```python
# ---- Paso 1: clasificar frame individual ----
raw_state = self._detector.classify(frame)

# Fallback deep detect S18: si classify se quedó en S12, intentar
# detección independiente de templates (3 indicadores visuales + 2 OCR).
if raw_state.code == "S12":
    deep = _deep_detect_s18(frame, self._ocr)
    if deep is not None:
        raw_state = deep

# Slot detection (sin cambios)
if raw_state.code == "S17":
    raw_state.slot = extract_s17_slot(frame, self._ocr)
elif raw_state.code == "S9":
    raw_state.slot = extract_s9_slot(frame, self._ocr)

# ---- Paso 2: alimentar buffer temporal ----
# Deep detect con alta confianza salta votación 2/3 → UX < 500 ms
if raw_state.method == "deep_detect" and raw_state.confidence >= 0.75:
    voted_state = buffer.promote_now(raw_state)
else:
    voted_state = buffer.add(raw_state)
```

### 2.1 `TemporalBuffer.promote_now()` — nuevo método

Emite el state inmediatamente, saltando la votación 2/3 estándar, pero
mantiene `_last_emitted` coherente para que el siguiente frame con el
mismo código devuelva `None` (dedup). Si después del S18 el usuario
navega a S15, los frames S15 ingresan a `add()` normal y a la mayoría
2/3 se emite S15 limpiamente.

### 2.2 StateMachine `_VALID_TRANSITIONS`

Se agregó `"S18"` a las transiciones permitidas desde `S13`, `S14`, `S16`
(detector.py:78-81). Hoy `StateMachine.validate()` no bloquea
transiciones inválidas — devuelve el código tal cual (línea 238). Pero
si se activa el modo estricto en el futuro, las nuevas transiciones
quedan cubiertas.

## 6. Riesgos conocidos y mitigaciones

| Riesgo | Mitigación implementada |
|--------|-------------------------|
| Tesseract no instalado en máquina del usuario → OCR siempre 0 → nunca llega a `deep_detect` | Path tentativo (conf 0.55) sigue funcionando con solo CLAHE (peso 2). Va por `buffer.add` 2/3 votos, latencia +300 ms pero no se pierde la detección. |
| Latencia OCR cada frame degrada heartbeat | Deep detect solo corre cuando `classify()==S12` (camino frío). En estados normales (S1, S8, S15, etc.) NO se ejecuta. |
| FP en S16 (modal Info conjunto) con OCR fallback | OCR del banner S16 retorna "Información del conjunto", no contiene keywords AGENT INFO → ocr_score=0 → como máximo tentativo. Test `test_falsos_positivos_no_se_detectan_como_s18_con_ocr_no_s18` lo confirma. |
| CLAHE indicador disparando en frames uniformes (carga, transición) | Filtros `std>15` + `text_area<0.95` agregados. Test `test_deep_detect_negro_total_sin_ocr_devuelve_none` lo verifica. |
| `promote_now` rompe la votación normal | Test `test_temporal_buffer_promote_no_rompe_voting_normal` verifica que tras promote, los siguientes frames de otro código pasan por voting 2/3 normal. |

## 7. Decisiones cerradas en esta sesión

1. **No se recapturan templates S18** — el deep_detect cierra el problema sin atar a una resolución específica. Las templates quedan como Capa 1 (cuando matchean, baratas y precisas); deep_detect es Capa 2 (resolución-agnóstica). Si en el futuro otras pantallas exhiben el mismo problema, se aplicará el mismo patrón antes que recapturar.
2. **El gating OCR es no-negociable para alta confianza** — sin señal textual, no hay distinción entre S18 y otros modales con grilla.
3. **`promote_now` no resetea el buffer** — agrega al window y marca `_last_emitted`. Esto deja la votación 2/3 lista para captar la SALIDA de S18 (ej. transición a S15) sin perder votos.
4. **CLAHE indicator se mantiene con peso 2** — es el más fuerte de los 4 visuales (7/7 fixtures), pero necesita filtros adicionales (`std`, `text_area<0.95`) para descartar FPs uniformes.
