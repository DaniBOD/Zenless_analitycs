**Lecciones aprendidas del proceso QA:**

1. **Templates basados en texturas genéricas → FP garantizado.** Resolución: usar SIEMPRE elementos con texto distintivo (footers, headers, breadcrumbs, etiquetas únicas).
2. **El threshold 0.85 es el sweet spot**: 0.70 produce FPs con elementos UI repetidos entre pantallas; 0.85 con templates específicos da TP > 0.95 y FP < 0.6.
3. **Heartbeats demasiado esparcidos (15s) ocultan el comportamiento del detector** en transiciones rápidas. 5s + cadencias por estado (1-1.5s en pantallas intermedias) es lo correcto.
4. **Dedup por transición ≠ dedup por tiempo**: capturar UNA vez al entrar a un disc-state (S3/S6/S7), resetear flag al salir.
5. **OCR del título "Set Name (N)" + regex `r"\((\d)\)"` con psm=6 es robusto** (12/12 S17, 6/6 S9).
6. **Templates de un mismo estado pueden ser múltiples** (S18 tiene s18a/s18b/s18c — variantes mutuamente excluyentes o redundantes).

### 7.1 TemporalBuffer — majority voting multi-frame

Nuevo `TemporalBuffer` en `detector.py` con ventana de 3 frames. Solo emite un cambio de estado cuando 2/3 frames coinciden (majority vote). Integrado en `monitor.py._run()`:
- Captura rápida cada **100ms** (10 fps)
- Procesamiento pesado (OCR, parseo) solo cuando el buffer confirma el estado
- Elimina FPs transitorios por ruido de un solo frame

### 7.2 Heartbeat 2s (antes 5s)

El heartbeat de diagnóstico pasa de cada 5s a cada **2s** para feedback más rápido.
